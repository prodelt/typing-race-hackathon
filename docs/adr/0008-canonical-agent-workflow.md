# One canonical agent workflow: wayfinder charts, Spec Kit builds, Claude Code is the only runtime

Wayfinder owns everything before a spec exists — fog, decisions, research — and hands off a roadmap. Spec Kit owns the artifact chain `specify → clarify → plan → checklist → tasks → analyze → implement → converge`, one chain per feature. Matt Pocock's practice skills (`tdd`, `code-review`, `diagnosing-bugs`, `codebase-design`, `domain-modeling`) are called *inside* Spec Kit steps, never as a competing artifact chain. The product is cut into five independently demonstrable features, each built by a short Foundational phase followed by two concurrent user-story lanes in git worktrees. Claude Code is the only wired-up runtime. Decided 2026-09-22, resolving [ticket 16](../../.scratch/typing-race-hackathon/issues/16-multi-agent-workflow-and-constitution.md) against the evidence in [research 07](../research/07-speckit-pocock-workflow.md).

## Considered options

**Running both tool sets in full.** `to-spec`, `to-tickets` and `implement-spec` duplicate `speckit-specify`, `speckit-tasks` and `speckit-implement`. Rejected because everything downstream of a spec — `plan`, `tasks`, `analyze`, `implement`, `converge` — reads `spec.md` from `FEATURE_DIR`, so a second spec published into `.scratch/` is invisible to all of it and creates two documents claiming to be current. Their genuinely distinct ideas are kept: `to-spec`'s "agree the test seams first" becomes a section of `plan.md`, and `to-tickets`' tracer-bullet rule is what cuts both the features and the user stories.

**`implement-spec` as the orchestrator.** It opens a draft PR, runs implementer subagents in worktrees and *merger* subagents that merge into the PR branch by themselves. Rejected on two counts: agent-run merges are incompatible with a protected `main` and a human squash-merge, and its nesting is precisely what exhausted the usage budget twice. Its frontier scheduling is kept, driven by the human across worktrees instead of by an orchestrator agent.

**One Spec Kit feature for the whole product.** Rejected because `tasks.md` is per-feature and would become a single file that every lane edits for weeks, and because a single spec that large cannot be reviewed or demonstrated in pieces.

**Five features cut by layer** — app core, dictionary pipeline, accounts, academy, races — which is what research 07 first proposed. Rejected: the dictionary pipeline has no user story at all, and Spec Kit's `tasks.md` is built around user stories with an "Independent Test" line, so a build-time concern does not fit the form. A layered cut also delays validation: a mistake in the pipeline's data shape would surface only weeks later, when the Academy finally consumed it. The features were re-cut vertically instead, and the pipeline moved inside the feature that first consumes it.

**Specialised agent roles** (`agent:architect`, `agent:logic-tdd`, `agent:ui-stitch`, `agent:backend-supabase`, `agent:judge-qa`), as `AGENTS.md` declared them. Dropped: current models handle any of these lanes without a role prompt, and the roles were drifting into fiction — they still referenced a Stitch project and tools this stack no longer uses. What the roles were really encoding, file ownership, is kept and made per-feature instead.

**Cross-tool parity with Antigravity, Codex and Gemini** (constitution v1.0.0 principle V). Dropped: it forces the Spec Kit skills into Antigravity's `.agents/skills/` layout, leaves every skill installed two or three times in one session — where the model may invoke a stale copy — and buys nothing, because no other runtime is actually used on this project.

## Consequences

- **The roadmap.** `specs/roadmap.md` lists five features, each a vertical slice that can be demonstrated on its own: `001-typing-core`, `002-accounts-and-progress`, `003-words-and-curriculum` (the dictionary pipeline is its Foundational phase), `004-academy-and-analytics`, `005-races-and-leaderboards`. Dependencies: 001 first; then 002 and 003 in parallel; then 004 (needs both) and 005 (needs 002). IDs are immutable once referenced, and scope shifts update the roadmap first.
- **Story, not task, is the unit of isolation.** One user story = one worktree = one branch = one PR. A task is one Conventional Commit and one `[X]` inside that branch; CI runs on every push, so a task still closes against a green run. `[P]` inside a story phase is a batching hint for that single lane and is never split across lanes.
- **Hot files belong to a Foundational phase, never to a story lane.** `package.json`, the lockfile, `tsconfig*`, Vite/Tailwind config, design tokens, CI workflows, the root router and shared barrels can only change in a feature's Foundational phase, which merges before that feature's stories fan out. "Lane 0" is therefore a role inside each feature, not a one-time global event.
- **File ownership is derived, not declared.** Every task in `tasks.md` carries an exact file path, so each feature's `plan.md` groups those paths by `[US]` label and asserts they are disjoint. Overlapping paths mean the stories are not independent, and that is fixed at `/speckit-tasks` before any lane starts.
- **The constitution becomes the test gate.** Spec Kit generates test tasks only when asked, so the Definition of Done lives in the constitution as MUST principles; `/speckit-analyze` then reports a story phase with no test tasks as CRITICAL before any code is written. Because that gate is a ratchet, Governance defines an explicit waiver: a `Waived:` line in the PR body plus a note in the feature's `plan.md`.
- **Six gates, no overlap:** `/speckit-analyze` on the artifacts, `/speckit-checklist` on requirement quality, TDD plus the story's Independent Test in the lane, `/code-review <merge-base>` in the lane before the PR, CI on the PR, and `/speckit-converge` once per feature, with a final `/code-review main...HEAD`.
- **Two concurrent lanes, ceiling three.** The binding constraint is one human reviewing PRs and the usage budget, not the tooling. No nested agents: `code-review`'s two sub-agents are the only sanctioned nesting, and `implement-spec`, `claude-handoff` and agent teams are out.
- **Handoff is a context pointer, never a copy.** A lane is started with the feature directory, the story id, its ownership lines and the branch; the PR body carries story id, tasks covered, Independent Test, `code-review` summary and the CI link.
- **Tooling follows.** Spec Kit switches to the `claude` integration with `--script ps`, so its skills live in `.claude/skills/`; the Spec Kit `git` extension stays uninstalled, because branch-per-feature and auto-commits would fight this git flow. `AGENTS.md` becomes the single canonical prose document, `CLAUDE.md` imports it, and `.gemini/GEMINI.md` is removed.
- **This supersedes part of [ADR-0001](0001-project-tooling-spec-kit-and-agent-skills.md)**: its cross-tool premise and its listing of `to-spec` / `to-tickets` / `implement` as equal alternatives no longer hold.
