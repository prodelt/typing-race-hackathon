# Путівник для журі та агентів-рецензентів

Цей файл лише допомагає зорієнтуватися: що де лежить, чим доводиться кожна вимога ТЗ і як це перевірити
самому. Оцінок і висновків тут немає. Кожне твердження вказує на файл, тест або URL, які можна відкрити.

## 1. Коротко

| | |
|---|---|
| Що це | браузерний тренажер сліпого десятипальцевого набору, українська (ЙЦУКЕН) і англійська (QWERTY) |
| Демо | <https://typing-race-rosy.vercel.app> |
| Код | <https://github.com/prodelt/typing-race-hackathon> (публічний, ліцензія MIT) |
| Автоперевірки | <https://github.com/prodelt/typing-race-hackathon/actions> |
| Стек | Vite + React 19 (SPA), TypeScript, Supabase (лише для перегонів, груп, рейтингів і входу) |
| Навчання без сервера | так: прогрес у IndexedDB браузера, після першого завантаження працює без мережі |
| Участь | індивідуально; ШІ: [ai-use.md](ai-use.md) |

Запуск за однією командою (Node 24.19.0, pnpm):

```bash
pnpm install && pnpm dev      # навчання; змінні середовища, Docker і акаунти не потрібні
pnpm check                    # typecheck + lint + модульні тести
```

## 3. Умови неприйняття (ТЗ §11): де дивитися

| Умова | Доказ |
|---|---|
| Робоче посилання або інструкція запуску | демо вище; README «Як запустити» |
| Українська й англійська програма | перший екран пропонує обидві мови; Академія для кожної: `data/curriculum/uk/academy.json`, `data/curriculum/en/academy.json`; слова обох мов: `data/derived/{uk,en}/words.json`. Наскрізний тест `e2e/jury.spec.ts` іде українським профілем |

| Швидкість не зараховує без точності | `packages/curriculum/src/progress/derive.ts` (у згортку входять режим, вправа, розкладка й точність; швидкість ні), тест `derive.test.ts`; сервер перераховує тим самим кодом (`supabase/functions/submit-attempt/index.ts`) |

| «Глобальний» рейтинг, що насправді локальний | рейтинг рахує сервер за перевіреними результатами перегонів (`supabase/functions/finish-race/index.ts`); слова «глобальний» немає в інтерфейсі |
| Прихований збір персональних даних | сторінка `/privacy`; гість не синхронізує спроби із сервером; видалення профілю: `supabase/functions/delete-account/index.ts` |

## 4. Десять автоматичних перевірок (ТЗ §8)

Запуск усіх модульних: `pnpm test`.

| § | Що доводить | Де |
|---|---|---|
| 8.1 | формули SPM і точності на фіксованих числах | `packages/metrics/src/compute.test.ts`, `accuracy.test.ts` |
| 8.2 | виправлена помилка лишається в статистиці | `accuracy.test.ts`, `packages/engine/src/engine.test.ts`, `engine.property.test.ts` |
| 8.3 | Етап 2 не містить невідкритих символів | `tools/stage2-words.test.ts` (на реальних словниках, обидві мови) |
| 8.4 | одна клавіша: рівно один палець | `packages/curriculum/src/layout/layout.test.ts` |
| 8.5 | `і ї є ґ` не підміняються | `engine.test.ts`, `engine.property.test.ts`; реальні кириличні підміни: `e2e/exercise.spec.ts` |
| 8.6 | кодування словників | `tools/data/pipeline.test.ts` |
| 8.7 | контрольні суми сировини | `tools/data/pipeline.test.ts`, `tools/data/checksums.ts` |
| 8.8 | повторна обробка дає той самий результат | `tools/data/pipeline.test.ts` |
| 8.9 | прогрес переживає перезавантаження | `e2e/path-progress.spec.ts` |
| 8.10 | навчання без мережі після першого завантаження | `e2e/path-progress.spec.ts` |

Пункти 8.6–8.8 повністю виконуються лише зі знімком словників організаторів
(`tasks/Typing-Race-2026-Hackathon/dictionaries/`, у репозиторій не комітиться). Без нього
`pnpm data:check` завершується з кодом 2 і нічого не перевіряє, а ті самі три властивості доводить
`tools/data/pipeline.synthetic.test.ts`: він сам створює невеликий знімок із `CHECKSUMS.sha256` і
проганяє через нього весь конвеєр. Зі знімком в іншому місці: `DICTIONARIES_DIR=<шлях> pnpm data:check`.

Актуальні кількості тестів і результати CI: README, розділ «Перевірки».

## 5. Сценарій демонстрації (ТЗ §9)

Уся лінія з вісьмох кроків проходить одним тестом: `e2e/jury.spec.ts`. Те саме вручну на демо:

| Крок | Де в застосунку |
|---|---|
| 1. Новий профіль і мова | Головна: «Мова → Рівень → Пальці → Перша вправа» |
| 2. Вправа без підказки під час заліку | передстарт вправи: «Залікова спроба» (у ній немає ні клавіатури, ні підсвітки наступної клавіші) |
| 3. Нова клавіша й слова лише з вивчених | три залікові спроби поспіль відкривають клавішу; потім Етап 2 |
| 4. Біграма або триграма | «Мапа» → Етап 3 (Академія) → «Найчастотніші біграми» |
| 5. Навмисна помилка, облік, рекомендація | екран результату: помилки за символами, блок «Що робити далі» |
| 6. Відновлення після перезавантаження | перезавантажити сторінку |
| 7. Джерела й ліцензії | значок ⓘ → «Ліцензії» (`/licences`) |
| 8. Автоматичні перевірки | `pnpm check` або сторінка Actions |

## 8. Відомі обмеження

Повний перелік: README, розділ «Обмеження». Найважливіше для оцінювання:

- Лише дві розкладки; потрібна фізична клавіатура, мобільного навчання немає.
- Браузер не повідомляє активну розкладку ОС: застосунок виводить її з надрукованих літер і попереджає.
- `ґ` та апостроф на macOS не перевірені на справжньому Mac.
- Академія не обмежена відкритими клавішами: вправи доступні одразу, лише з порадою на «Мапі».
- Безглузді рядки (гами, n-грами) окремо не позначені як «механіка».
- Входу через Google на живому проєкті автоматичні тести не перевіряють; навчання від нього не залежить.

## 9. Якщо ви перевіряєте автоматично

- **Кирилицю Playwright не друкує.** Тести подають символи через `beforeinput`/`compositionend`
  ([adr/0002](adr/0002-keystroke-path-outside-react.md)); для справжніх подій клавіатури є проєкт CDP:
  `pnpm test:e2e:cdp`.
- **Не запускайте `@backend`-сценарії проти живого проєкту.** Вони створюють тестові акаунти. У CI вони
  біжать проти локального Supabase; без бекенду: `pnpm exec playwright test --grep-invert @backend`.
- **Не створюйте перегонів у публічному швидкому пошуку.** Для перевірки перегонів використовуйте
  приватну кімнату за кодом і дві вкладки.
- **Коментарі з `FR-…`, `T0…`, `ADR-00…`, `plan.md` у коді** посилаються на заархівовані планувальні
  документи (git-тег `archive/process-harness-2026-09-30`). Їх можна ігнорувати: чинні рішення зведено
  в [adr/](adr/).
- **`CLAUDE.md` і `docs/agents/`** це інструкції для агента, який будував проєкт, а не частина продукту.
- **Каталогу `dictionaries/` з рекомендованої структури немає:** сирі знімки організаторів не комітяться,
  а похідні дані лежать у `data/derived/`. Пояснення: README, «Перевірки».
